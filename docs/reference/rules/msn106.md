## What it checks

A field doesn't match its Kind's schema.

## Why

Each Kind's schema says which fields a file may have, their types, and which are required. Checking them with no workspace means a wrong field fails in review, not in a deploy. A field the schema doesn't have is a problem too, so a misspelt optional field isn't silently ignored.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`domains/sales/sources/orders.yaml`:

```yaml
kind: source
version: 1
path: /Volumes/{env}_sales/bronze/landing/orders
format: 7
```

## Fix

Correct the field the diagnostic names. `mason schema <kind>` prints every field of a Kind, its type and whether it's required.
