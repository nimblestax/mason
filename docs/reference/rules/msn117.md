## What it checks

A config file's name isn't an identifier, so the table named after it can't be written in SQL: it must hold only letters, digits and underscores, and not start with a digit.

## Why

A Source, Seed or Gold Model takes its table's name from its config file's name, and SQL reads that table by name. A name with a hyphen or a space, or one that starts with a digit, would need quoting everywhere it's read.

## Example

Write these files into the project `mason init` creates, and `mason validate` fails:

`domains/sales/seeds/vat-rates.yaml`:

```yaml
kind: seed
version: 1
file: vat-rates.csv
columns:
  code: STRING
```

`domains/sales/seeds/vat-rates.csv`:

```csv
code
AU
```

## Fix

Rename the file to a name of letters, digits and underscores, such as `vat_rates.yaml`, which the diagnostic suggests.
