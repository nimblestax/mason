## What it checks

A Source's `silver` block has `keys` but no `sequence_by`.

## Why

With `keys`, silver keeps one row per key and applies each change to it. Changes can arrive out of order, so Mason needs a column that says which change is newest. Without one, an older change could overwrite a newer one.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`domains/sales/sources/orders.yaml`:

```yaml
kind: source
version: 1
path: /Volumes/{env}_sales/bronze/landing/orders
format: json
silver:
  keys: [order_id]
```

## Fix

Add `sequence_by` with the column that orders the changes, such as `updated_at`, or remove `keys` to append every row.

## Principle

This Rule enforces [Silver is typed, deduplicated and conformed](https://nimblestax.com/way/silver-is-typed-and-conformed), from the Nimblestax Way.
