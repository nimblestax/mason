## What it checks

A Source's `silver` block has `sequence_by`, `scd` or `delete_when` but no `keys`.

## Why

These fields shape an upsert: which change is newest, whether history is kept, and which change is a delete. Each works on the rows of one key. Without `keys`, silver appends every row, so the field would do nothing while looking as if it did.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`domains/sales/sources/orders.yaml`:

```yaml
kind: source
version: 1
path: /Volumes/{env}_sales/bronze/landing/orders
format: json
silver:
  scd: 2
```

## Fix

Add `keys` with the columns that identify a row, or remove the field to append.

## Principle

This Rule enforces [Silver is typed, deduplicated and conformed](https://nimblestax.com/way/silver-is-typed-and-conformed), from the Nimblestax Way.
