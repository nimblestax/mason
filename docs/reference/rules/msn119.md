## What it checks

A Source's `silver.sequence_by` isn't one SQL expression on one row, such as `updated_at` or `struct(updated_at, seq)`: it doesn't parse, or it holds a query, an aggregate, a window function, a comment or an alias.

## Why

`sequence_by` orders the changes to each key, so silver keeps the newest. Mason places it inside the code it generates, so it must be one expression on the change's own columns. A sort direction such as `DESC` reads as an alias, and has no place there: the highest value is always the newest.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`domains/sales/sources/orders.yaml`:

```yaml
kind: source
version: 1
path: /Volumes/{env}_sales/bronze/landing/orders
format: json
silver:
  keys: [order_id]
  sequence_by: updated_at DESC
```

## Fix

Write `sequence_by` as the column that orders the changes, such as `updated_at`, or one expression on the row's own columns, such as `struct(updated_at, seq)`.
