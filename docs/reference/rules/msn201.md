## What it checks

SQL reads a table that isn't in the project.

## Why

Mason knows every table a project makes: each Source's bronze and silver tables, each Seed's table and each Gold Model's table. SQL reads them by Logical Name, such as `sales.silver.orders`, so Mason can check every read before a deploy and point it at the right catalog in each Environment. A read it can't find is a typo, or a table nothing in the project makes. A table name without its Domain and Layer that isn't a CTE is reported too, because Mason can't tell which table it means.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`domains/sales/models/fct_orders.sql`:

```sql
SELECT order_id, amount
FROM sales.silver.order
```

## Fix

Declare a Source, Seed or Gold Model with this name, or correct the Logical Name.

## Principle

This Rule enforces [Every catalog is one domain in one environment](https://nimblestax.com/way/every-catalog-is-one-domain), from the Nimblestax Way.
