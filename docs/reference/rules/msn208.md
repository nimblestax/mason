## What it checks

Gold Models read themselves, or each other in a loop, so none of them can run first.

## Why

Mason builds each Gold Model after the tables it reads. When Gold Models read each other in a loop, every one of them waits for another, so there is no order to build them in.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`domains/sales/models/fct_orders.sql`:

```sql
SELECT order_id, amount
FROM sales.gold.fct_orders
```

## Fix

Remove one of the reads in the loop, which the diagnostic lists, so each Gold Model reads only tables built before it.
