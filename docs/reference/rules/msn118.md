## What it checks

A Source's `silver.delete_when` isn't one SQL condition on one row, for the same reasons as `MSN116`.

## Why

`delete_when` decides, change by change, whether a change deletes its key's row, so it can see only that change. Mason places it inside the code it generates, so it must parse on its own, and a comment would hide the code after it.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`domains/sales/sources/orders.yaml`:

```yaml
kind: source
version: 1
path: /Volumes/{env}_sales/bronze/landing/orders
format: json
silver:
  keys: [order_id]
  sequence_by: updated_at
  delete_when: op = 'D' -- deletes from the source system
```

## Fix

Write `delete_when` as one condition on the row's own columns, such as `op = 'D'`.

## Principle

This Rule enforces [Silver is typed, deduplicated and conformed](https://nimblestax.com/way/silver-is-typed-and-conformed), from the Nimblestax Way.
