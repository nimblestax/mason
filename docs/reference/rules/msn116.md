## What it checks

An Expectation's `expect` isn't one SQL condition on one row: it doesn't parse, or it holds a query, an aggregate, a window function, a comment or an alias.

## Why

An Expectation is checked on each row as it's written to silver, so its condition can see only that row. A query, an aggregate or a window function reads other rows, and a rule across rows is a Test. Mason places `expect` inside the code it generates, so it must parse on its own, and a comment would hide the code after it.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`domains/sales/sources/orders.yaml`:

```yaml
kind: source
version: 1
path: /Volumes/{env}_sales/bronze/landing/orders
format: json
silver:
  expectations:
    - name: amount_is_positive
      expect: amount > (SELECT avg(amount) FROM sales.silver.orders)
```

## Fix

Write `expect` as one condition on the row's own columns, such as `amount > 0`. A rule across rows is a Test.

## Principle

This Rule enforces [Expectations guard rows; tests guard datasets](https://nimblestax.com/way/expectations-guard-rows), from the Nimblestax Way.
