## What it checks

A row of a Seed's file has the wrong number of values, or a value that doesn't fit its column's type.

## Why

Mason checks a Seed's values before deploying it, so a typo in the CSV file fails in review rather than when the table loads.

## Example

Write these files into the project `mason init` creates, and `mason validate` fails:

`domains/sales/seeds/countries.yaml`:

```yaml
kind: seed
version: 1
file: countries.csv
columns:
  code: STRING
  population: INT
```

`domains/sales/seeds/countries.csv`:

```csv
code,population
AU,26 million
```

## Fix

Give each row one value per column, quoting any value that contains a comma, and make each value fit its column's type, or change the type.
