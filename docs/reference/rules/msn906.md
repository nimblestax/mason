## What it checks

The refresh failed because a pipeline names a column its table doesn't have, often an Expectation on a column bronze doesn't have yet.

## Why

`mason deploy` refreshes an Environment's tables after it ships them, and reports a pipeline's own error when an update fails. When an Expectation checks a column that arrives in the same change, the silver flow fails on the unknown column before bronze runs, so bronze never picks the column up, and landing new data doesn't help.

## Example

A Source's files gained a `region` column, and an Expectation on `region` was added in the same change. In a project, this fails:

```console
$ mason deploy --env dev
```

## Fix

Correct the column's name. If an Expectation names a column bronze doesn't have yet, deploy without the Expectation so bronze picks up the column, then add it back. See [Recover from a failed refresh](../../guides/recover-from-a-failed-refresh.md).
